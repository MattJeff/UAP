# CORRECTION — the AI-labelling claim, verified against the bytes before sealing

**Status: resolved. This is the blocking item; the manifest was not sealed until it was settled.**

## The risk

The forensic claim distinguishes **montage** (proven) from **AI generation** (not proven). A manifest is sealed with SHA-256, so any false statement inside it is a false statement *cryptographically bound to authentic files* — the worst possible place for an error. The specific danger: asserting "no AI-generation marker / zero `generated`" when the token `generated` (or `genai`) in fact appears somewhere not scanned.

## What was actually scanned

For all 14 files, **both** layers:
1. **Parsed metadata** — `exiftool -a -G1 -s -json` (all tags, all segments exiftool recognizes).
2. **Raw bytes** — `grep -aoiE` directly on the file (catches strings in segments exiftool may not surface).

Plus the **official catalogue** `uap-data.csv` (all 1,555 physical lines).

## The finding that the naïve claim would have gotten wrong

- `genai` → **0** occurrences in all 14 files (raw bytes) **and** 0 in `uap-data.csv`.
- C2PA / JUMBF / Content-Credentials → **0** in all 14 files.
- `artificial`, `synthetic` → **0** in all 14 files and 0 in the CSV.
- `generated` → **1 occurrence in 7 of the 8 FBI files** (`D016–D020, D022, D023`); **0** in the 6 NASA files and in `FBI-UAP-D021`.

That last line is the trap. The exiftool **parsed** dump shows 0 `generated`, but the **raw bytes** contain it. Resolving the discrepancy:

- The token is **`autoGenerated`** — an Adobe **Photoshop image-slice attribute**, part of the same slice records named `Witness_01-UAPs-SCENE1/2/3`. Its value indicates whether a slice was user- or auto-created. **It has nothing to do with AI generation.**
- It is present only in the FBI files that *carry* Photoshop slice metadata; absent in `D021` (no metadata) and in the Illustrator-produced NASA files. Consistent, explained, benign.
- exiftool did not surface it as a plain tag value (hence 0 in the parsed dump), which is exactly why the **raw-byte scan was necessary**. This is the methodological point in miniature: *scan the bytes, not just the parser's summary.*

## The corrected, scoped claim now sealed in the manifest/README

> Across the 14 files (raw bytes **and** parsed metadata) and the official `uap-data.csv`: **0** `genai.mil`, **0** C2PA/Content-Credentials, **0** `artificial`/`synthetic`. The only `generated` token present is Adobe's benign **`autoGenerated`** slice attribute (7/8 FBI files). Therefore **montage/compositing is byte-proven; AI generation is neither present in the files nor disclosed in the catalogue.**

## How `reproduce.sh` enforces it

The detector reports, per file, `gen=N(auto=N,other=N)` where `other = generated − autoGenerated`, and the run **asserts `other == 0` across all 14 files** (a `FAIL` if any bare `generated`/AI token ever appears). It also asserts `genai == 0`, `c2pa == 0`, `artificial/synthetic == 0`. So the corrected claim is not a footnote — it is a machine-checked gate that a reviewer re-runs.

## Bearing on the wider record

This also disposes of the frequently-repeated third-party line that the images were *"artificially generated using genai.mil."* That disclaimer is **not in these files** and **not in the official CSV**; it traces to secondary commentary and is **unconfirmed** against the primary bytes. The catalogue's own labels are "Digital Rendering" (orbs) and "archival photograph … modified" (NASA) — never "AI."
